## 6. P-S5-4 — 등록 산식과 기전이 어긋난다 → **갈래 B 확정**(G2 §2)

등록 산식: "격차가 처음 0.5 %p 를 넘는 L 에서의 **K비(bl_lr)**".
실측: 격차 0.5 %p 교차 **L ≈ 331** → **K비(bl_lr) = 0.73 → 갈래 A**.

그러나 **그 지점에서 격차를 만드는 비교군은 bl_lr 이 아니라 bl_loc_pri** 다
(200·450 에서 최선 비교군 = loc_pri). 짝을 맞추면 **K비(loc_pri) = 1.49 →
갈래 B**. 등록 산식이 "최선 비교군 기준 격차"와 "bl_lr 기준 K비"를 **다른
정책에 걸어둔 것**이 원인이고, 산식대로의 0.73 은 **아무 정책의 용량 상태도
가리키지 않는 값**이다.

- 갈래 A(원 문구 유지)는 §4.2 에 유리한 결론이므로, 산식이 기전과 어긋난
  것을 알고도 A 를 취하는 것은 지시 §2 의 "유리한 해석 금지"에 어긋난다.
- **확정: 갈래 B 적용**(G2 §2 승인 — 산식 결함이 만든 유리한 결론 A 는 기각). 변별 개시 K비 **1.49**(범위 1.2~2.0). §4.2 교체 문구:
  > 우위는 용량 무릎 자체가 아니라 **무릎을 일정 배율 초과한 구간**에서
  > 발생한다. 무릎 부근에서는 LB 의 큐잉이 초과분을 흡수하므로 배정 정책의
  > 차이가 드러나지 않고, 흡수 여력이 소진되는 지점부터 격차가 열린다.

  실측이 이 서술과 정합한다: loc_pri 는 K비 0.90(L=200)에서 0.226 %로 멀쩡
  하고, K비 2.02(L=450)에서 4.16 %로 열화한다 — 무릎 통과 직후가 아니라
  **1.5 배 부근에서** 갈린다.
- **부기(§4.2 에 없던 두 번째 축)**: bl_lr 대비 격차는 **부하와 무관하게
  전 구간 존재**한다(L=200, K비 0.42 에서도 **8.2 %p**). 기전은 용량이
  아니라 **거리 × 밴드**다 — `s5_lr_L200_1` 에서 S3_search 위반 **100 %**
  인데 f_c p95 는 3.8 ms(서버는 한가하다). d_net(S3) 25 ms + 밴드 d_acc
  (4474 B / 1600 kbit ≈ 22 ms) + 처리시간 > SLO 45 ms 라 **구조적으로 불가**
  하다. SORTS 는 이 구간에서 search 를 전량 S1 로 보내(66.6 rps, K비 0.63)
  회피한다. 즉 "우위는 용량 경계에서 나온다"는 **최선 비교군(loc_pri) 기준
  서술**이고, **least-request 대비 우위는 용량 이전에 거리·클래스 축에서
  이미 발생**한다. 이 축은 §4.2 문구를 약화시키지 않고 범위를 넓힌다.

## 7. §4.2 수정 — 우위는 **두 축**에서 나온다 (G2 §5 확정)

1. **확정 서술**: 우위는 두 기전에서 나온다.
   - **① 저부하 전 구간 — 거리 × 밴드로 애초에 불가능한 사이트를 배제**
     (층 1·2). 실측: L = 200, K비 0.42 에서도 `bl_lr` 대비 **8.2 %p**.
     기전은 용량이 아니라 **SLO 예산의 구조적 소진**이다 — search(4474 B)
     의 밴드 전송 d_acc ≈ 22~25 ms 에 d_net(S3) 25 ms 를 더하면 SLO 45 ms
     예산이 **음수(−9.6 ms)** 가 되어, 서버가 한가해도(f_c p95 3.8 ms)
     S3 로 간 search 는 **부하와 무관하게 100 % 위반**한다(§9-(iii) 표).
   - **② 무릎 1.5~2 배 구간 — 용량 경계에서 엣지 보존**(층 4·6). 실측:
     `bl_loc_pri` 대비 격차가 K비(loc_pri) 1.49 에서 열려 L = 800 에서
     최대(+4.27 %p).
   - **비교군에 따라 드러나는 축이 다르다**: `bl_lr` 은 ①, `bl_loc_pri`
     는 ②. 이것이 논문 §6 에서 **비교군을 왜 둘 다 두었는가**의 답이다 —
     하나만 두면 축 하나를 못 본다.
2. **수정 범위를 정확히**: 야간 §4.2 의 판정 "**radio 축 단독으로는 정책
   변별 불가**"는 *무선 축 스윕*(밴드를 바꾸고 부하를 고정)에서 나온
   결론이고 **그대로 유효**하다. 이번은 *부하 축 스윕*(밴드를 고정하고
   부하를 바꿈)이며, 거기서 **새 기전(①)이 추가**된 것이다. 두 축의
   결론을 뭉뚱그리지 않는다 — ①은 "무선 단독으로 변별된다"는 주장이
   아니라 "밴드가 걸린 상태에서 거리 × 응답크기가 클래스별 실행 가능성을
   결정한다"는 주장이다.
3. **경계 위치**(P-S5-4 갈래 B, §6)와 **유효 범위**(K비 ≈ 2, §0)는
   ② 축의 서술이다.

### 9.2 (iii) 총수요 > 총용량 — 배정 무관 하한

`SLO − GB − d_net − d_acc(class)` 로 계산한 밴드 창의 **구조적 실행 가능성**:

| 클래스 | 수요 rps | d_acc | S1 | S2 | S3 |
|---|---|---|---|---|---|
| search | 466.7 | 24.6 ms | +13.4 ms | **+0.4 ms** | **−9.6 ms(불가)** |
| reserve | 311.1 | 0.2 ms | +27.8 | +14.8 | +4.8 |
| recommend | 622.2 | 1.1 ms | +26.9 | +13.9 | +3.9 |

- **search 는 사실상 S1 전용**이다(S2 예산 0.4 ms = 서버가 완전히 한가할
  때만, S3 는 불가). S1 의 밴드 유효 용량 K = 105.4 eq 이므로
  **어떤 배정 정책으로도 (466.7 − 105.4)/1400 = 25.8 %p 는 위반**한다.
- 실측 대비: **bl_lr 30.9 % = 하한 + 5.1 %p**(거의 최적), **SORTS 46.8 %
  = 하한 + 21.0 %p**. 즉 **(iii) 은 위반 "수준"의 대부분을 설명하지만
  격차에는 0 을 기여**한다(양 정책 공통). 30 % 기준(G2 §4.1-2)에는
  **미달**이므로 "둘 다 불가능 영역"으로 축소되지 않는다 — `bl_lr` 이
  하한 근처에 있다는 사실이 그 축소를 막는다.

### 9.3 (i) C_eff 테이블 비대칭 — 반사실 결정 재계산 (실행 없음)

`sorts_ctl.Controller` 의 **실제 메서드**(`capacity_filter`/`soft_alloc`/
`shares_of`/`_cap_room`)에 L = 1400 런의 **로그된 slack·유닛 rps** 를 다시
넣고, `c_eff_band` 만 바꿔 배정이 어떻게 달라지는지 재계산했다(both 창
55 tick × 2 런). **가정값임을 명시**하고 민감도로 3 안:

| 시나리오 | S1 | S2 | S3 | EXP 틱 | cap 차단 |
|---|---|---|---|---|---|
| 기준(실측 배치 — S1 만 밴드값) | 14.8 % | 39.2 % | 46.1 % | 110 | 128 |
| 가정 A — S2/S3 도 S1 과 같은 하락률 ×0.511 | 14.8 % | 30.0 % | 55.2 % | 116 | 169 |
| 가정 B — 완만 ×0.784 | 14.8 % | 33.0 % | 52.3 % | 110 | 136 |
| **가정 C — 거리 보정(S2 ×0.35, S3 ×0.15)** | **56.5 %** | 25.3 % | 18.2 % | 193 | 403 |

- **비례 축소(A·B)로는 고쳐지지 않는다 — 오히려 나빠진다.** 원거리 room 이
  여전히 크기 때문에 손실 배분 그리디가 **S3 로 더 몰아준다**(46 → 55 %).
- **거리 보정(C)에서만 뒤집힌다**: S1 몫이 14.8 → **56.5 %** 로, 실측에서
  하한 근처를 달성한 `bl_lr`(S1 37 %)과 같은 방향이 된다. 즉 문제는 "S2/S3
  값이 비어 있다"가 아니라 **"비어 있는 값이 하필 거리 × 밴드 상호작용을
  담는 자리"** 라는 것이다(§9.2 표가 그 상호작용의 정체다).

### 9.4 (ii) 고부하 진동 — 배정 버스트성

초당 사이트 도착의 변동계수(both 창):

| 런 | S1 | S2 | S3 |
|---|---|---|---|
| SORTS 1400 (2런) | 0.10 / 0.11 | **0.32 / 0.46** | **0.24 / 0.30** |
| bl_lr 1400 (2런) | 0.10 / 0.10 | 0.09 / 0.09 | 0.09 / 0.09 |

- SORTS 의 S2/S3 도착은 `bl_lr` 보다 **3~5 배 버스트**하다(피크/평균 1.5).
  같은 평균 부하(S2 546 vs 508)에서 S2_search 위반이 99.4 % vs 45.9 % 인
  이유가 이것이다 — S2 의 search 예산이 **0.4 ms** 뿐이라 순간 큐가
  곧바로 SLO 를 넘긴다. subset 전환 245~264 회(800 의 24~31 대비 8~10 배).
- 다만 이 진동은 **독립 원인이 아니라 (i) 의 결과**다: 원거리 room 이 크게
  잡혀 계획 적재가 경계 부근을 왕복한다.

### 9.5 판정 — **(i) 지배** (G2 §4.2 분기)

| 원인 | 크기 | 근거 |
|---|---|---|
| **(i) C_eff 테이블 비대칭** | **볼륨 10.24 + 교차 4.53 = 14.77 %p (순 격차의 93 %)** | 배정이 S1 −423 / S3 +384 로 옮겨간 것이 손실의 직접 원인. 반사실 C 에서 S1 몫 14.8 → 56.5 % 로 역전 |
| (ii) 고부하 진동 | 위반율 효과 12.22 %p 중 S2 계열 ≈ 8 %p — 단 **(i) 의 파생** | CV 0.32~0.46 vs 0.09, 전환 245~264 |
| (iii) 총수요 > 총용량 | 격차 기여 **0**(수준 기여 25.8 %p) | 양 정책 공통 하한, `bl_lr` 은 하한 +5.1 %p |

→ **(i) 이 절반을 넘는다.** G2 §4.2 의 첫 갈래에 해당하므로 다음 실험
후보는 **`C_eff(S2/S3, band)` 측정**이다. 다만 §9.3 이 보여주듯 **비례
축소 값으로 채우면 악화**하므로, 측정 설계는 **(site × class × band)**
단위여야 한다 — 밴드가 SLO 예산을 잠식하는 크기가 응답 크기(클래스)와
거리(사이트)에 동시에 의존하기 때문이다. §9.2 의 예산 표는 그 중
**불가능 판정(예산 ≤ 0)은 런 없이 계산**되고, **유한 예산 칸(S2 search
+0.4 ms, S3 recommend +3.9 ms)만 실측이 필요**함을 알려준다.

**§6.4 절단 근거의 부하 조건부성 기록(G2 §4.2 지시)**: "잔여 6.5 % 는 용량
부정확이 원인이 아니다"라는 절단 근거는 **L = 800 에서 참**이었고(그 점의
SORTS S1 K비 0.92 로 용량 게이트가 정확히 작동), **L = 1400 에서는 거짓**
이다. 절단 판단이 **부하 조건부**였다는 사실을 여기 남긴다.
