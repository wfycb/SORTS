## 0. 왜 이걸 B보다 먼저 하는가

작업 A는 서버 축에서 본명제를 세웠지만(전환 78→4, 위반 0.89→0.12 %),
**무선(radio/edge) 축의 절대 수치에는 지금 어떤 신뢰구간도 못 붙인다.**
커넥션 단위 위반율이 양봉으로 갈라지고(정상 ~0.5 % / 열화 두 자릿수),
몇 개가 열화 쪽으로 뽑히는지가 런마다 다르기 때문이다(I-8).

문제는 **작업 B의 검증도 결국 이 축에서 이뤄진다**는 것이다. 용량 제약을
넣어 엣지 경합을 개선해도, 개선분이 복권 분산에 묻히면 측정이 안 된다.
그러므로 순서는 **측정 도구를 먼저 고친다 → 그 다음 B**다.

작업 A가 이미 조건부 형태로는 주장을 세웠다(§3: 열화 커넥션 하나가
겪는 피해 17.0 % vs 39.4 %). C의 목표는 이 조건부 주장을 **무조건부로
승격**하거나, 최소한 **조건부 추정량을 통계적으로 정당화**하는 것이다.

## 1. 목표와 성공 기준

다음 중 **하나 이상**을 달성하면 C는 성공이다. 우선순위 순.

| | 결과 | 성공 기준 |
|---|---|---|
| C-α | **기전 규명 + 제거** | 열화 커넥션을 만드는 계층을 특정하고, 설정 변경으로 제거. 동일 조건 반복 런 n≥5에서 열화 커넥션 0개, 위반율 런간 CV < 10 % |
| C-β | **기전 규명 + 통제** | 제거는 못 해도 원인 변수를 알아내 런간 균질화(예: 커넥션 수/포트/큐 배정 고정). 반복 런에서 열화 개수 분산이 유의하게 감소 |
| C-γ | **측정 프로토콜** | 기전을 못 밝혀도, 복권을 뚫고 정책 효과를 재는 추정량과 반복 설계를 확정. radio 축 비교에 ± 신뢰구간을 붙일 수 있게 됨 |

**C-γ는 최소 요구다.** α/β가 실패해도 γ 없이는 종료하지 않는다.
γ의 구체 형태는 §5에 후보를 적어 뒀다.

## 2. 이미 아는 것 (다시 조사하지 말 것)

### 2.1 I-8 기록 (Phase 4 ~ 작업 A)

- 무선 축 위반율이 **커넥션 단위로 양자화**된다. Phase 4 R1은 16개 중
  4개가 33~67 %, demo D4는 ~10개가 열화.
- **런 단위 추첨이다**: 같은 날 17분 간격의 A1(열화 0개, 계 0.31 %) vs
  A3(2개 33.8/33.4 %, 계 4.42 %). 공유기 교체 가설은 불필요해졌다.
- 같은 런 안의 arm 비교(const vs both, shadow)는 영향 없음 — 복권은
  런 사이에서만 문제가 된다.
- 사이트 분배·e2e p50·서버측 `f_c`·응답 바이트·조인율·이탈은
  전부 정상. **다른 것은 접근측 꼬리뿐이다.**

### 2.2 작업 A 개정 2에서 새로 확인한 것 (2026-08-10)

`analysis/taskA/pa_conn_edge.py` + 오프라인 감별(read-only):

| 런 / 창 | 열화 / 정상 | 열화 그룹 service p50/p95 | 정상 그룹 service p50/p95 | 열화 send지연 p95 |
|---|---|---|---|---|
| T10 far_tier / c1단독극단 | 5 / 11 | 30.3 / **41.5** ms | 28.1 / 32.0 ms | 4.6 ms |
| T11 strict_far / c1단독극단 | 9 / 7 | 30.4 / **52.6** ms | 28.3 / 32.8 ms | 23.1 ms |
| T9 far_tier / radio during | 1 / 15 | 27.1 / **43.8** ms | 22.6 / 37.9 ms | 7.3 ms |
| T8 strict_far / radio during | 4 / 12 | 32.6 / **48.9** ms | 27.5 / 36.7 ms | 8.9 ms |

여기서 나오는 **결정적 단서 셋**:

1. **생성기 백로그 단독 설명은 기각된다.** 열화 커넥션은 `corrected_ms`만
   나쁜 게 아니라 **`service_ms`(순수 응답시간) 자체가 나쁘다**(p95
   41.5 vs 32.0). CO 보정 인공물이 아니라 실지연이다.
2. **그러나 백로그도 동반한다.** 열화 커넥션의 send 지연(스케줄 대비)
   p95가 4.6~23.1 ms인데 정상은 **0.1 ms로 완전히 깨끗**하다. 즉
   열화 커넥션에서만 발사가 밀린다 — 2차 효과이거나 되먹임 고리다.
3. **p50은 거의 같고 꼬리만 갈라진다**(30.3 vs 28.1 = 2 ms 차).
   커넥션이 상시 느린 게 아니라 **간헐적으로 큐가 쌓였다 빠진다.**
   "느린 커넥션"이 아니라 "정체하는 커넥션"이다.

### 2.3 구조 지표는 복권과 독립이다

결정 로그(`decisions.csv`) 기반 지표 — 집합 전환 횟수, S1 포함/단독
tick 비율, EXPECTANT 비율, `f_c` 관측값 — 는 커넥션 복권의 영향을 받지

## 3. 가설과 감별 실험

`service_ms` 실지연 + 간헐 정체 + 커넥션 단위 고착 — 이 셋을 동시에
만족해야 한다. 순위는 사전 확률 순.

### H1. 접근측 셰이핑 계층의 per-flow 큐 배정 (최유력)

밴드(`tc` netem/htb)가 커넥션을 해시로 큐/버킷에 매핑하고, 충돌한
커넥션들이 한 버킷을 공유해 정체한다. 커넥션 수명 내내 같은 버킷이므로
**고착**되고, 어느 커넥션이 충돌하는지는 소스 포트에 달렸으니 **런마다
추첨**이 된다.

- **감별**: 열화 커넥션의 소스 포트를 수집해 `(port mod N)` 류의 패턴을
  본다. qdisc를 `fq_codel`/`sfq`(해시 기반) ↔ `pfifo`(단일 큐)로 바꿔
  양봉이 사라지는지 본다. `tc -s qdisc/class show`로 백로그·drop을
  **커넥션 수가 아니라 큐별로** 읽는다.
- **예측**: pfifo 단일 큐로 바꾸면 양봉이 사라지고 전 커넥션이 균일하게
  나빠진다. 이게 관측되면 H1 확정.

### H1b. HTB/버킷 클래스 공유 — 커넥션보다 클래스가 적다 ★**확정**

셰이핑 클래스(버킷)가 커넥션 수보다 적거나, 해싱 결과 여러 커넥션이 한
클래스에 들어가면 **명목 대역을 나눠 갖는다**. 2개 공유면 절반, 3개면 1/3 —
Phase 4 의 0/33/66/97 % 정수비 양자화가 여기에 잘 맞는다. 해시 충돌은
그런 깔끔한 정수비를 만들 이유가 없다는 지적이 정확했다.

- **감별**: `tc -s class show dev ogstun` 으로 클래스별 커넥션 수·실효
  rate·백로그를 뽑는다. 밴드 스크립트를 정독해 클래스 개수와 분류 키를
  먼저 확인한다. 비용 0.
- **판정 (C0 완료)**: **맞다.** 다만 H1(해시)과 **별개가 아니었다** —
  `tb-radio2.sh` 는 코호트당 `DIVISOR=64` 개 버킷을 만들고 각 버킷이
  독립 HTB leaf + netem 인데, **배정 키가 dst 포트 하위 6비트 해시**다.
  즉 *해시 충돌 = 클래스 공유*가 같은 사건이다. 커넥션 16개 / 버킷 64칸
  → 충돌쌍 기대값 1.875. 검증 전문은 `TASKC_REPORT.md` §2.

### H2. UE 스택(uesimtun / GTP) per-flow 처리

UERANSIM UE의 터널 처리나 GTP 캡슐화 경로에서 플로우별 처리량 편차.

- **감별**: 코호트를 **UE 하나 대신 둘**로 쪼개 같은 총 rps를 내고,
  열화가 UE 경계를 따라가는지 본다. 또는 밴드를 UE 쪽이 아니라
  **host-eno1 쪽에 주입**해 UE 스택을 우회했을 때도 양봉이 남는지 본다.
  (경로 손실 vs 서버 지연 구별에 쓰던 기법과 같다.)
- **예측**: host측 주입에서 양봉이 사라지면 H2, 남으면 H1/H3.

### H3. front-envoy 다운스트림 커넥션 처리

Envoy가 다운스트림 커넥션을 워커 스레드에 배정하고, 한 워커에 몰린
커넥션들이 경합한다.

- **감별**: `concurrency`(워커 수)를 1로 고정했을 때와 기본값일 때 양봉
  비교. Envoy `listener`/`worker` 통계(`downstream_cx_*`, per-worker
  `dispatcher` 지연)를 읽는다. front-envoy는 **재기동 가능**하다
  (사이트 컨테이너와 달리 무상태 — ISSUES.md 운영 규칙 참조).
- **예측**: 워커 1개에서 양봉이 사라지면 H3.

### H4. 생성기측 커넥션별 되먹임 (2차 효과로 강등)

HTTP/1.1 커넥션 직렬화 때문에 한 번 느린 응답이 뒤 요청을 밀고, 밀린
채로 자기 지속한다.

- **상태**: §2.2 단서 1이 **단독 원인으로는 기각**했다(`service_ms`
  자체가 나쁨). 다만 단서 2(send 지연 0.1 → 23 ms)는 되먹임이 **증폭기**로
  작동함을 시사한다.
- **감별**: 커넥션당 rps를 낮추고 커넥션 수를 늘려(예: 16×25 → 32×12.5)
  커넥션당 이용률을 낮췄을 때 양봉의 **심도**가 줄어드는지 본다.
  없어지지 않고 얕아지기만 하면 증폭기 판정.

### H5. 순수 통계적 인공물 (기각 대상)

16개 커넥션에 위반이 무작위로 흩어진 것이 우연히 양봉처럼 보이는 것.

- **감별**: 이미 사실상 기각됐다 — 정상 그룹 send 지연 p95가 0.1 ms로
  **완전히 깨끗**한데 열화 그룹만 4.6~23.1 ms다. 우연이면 이런 이분법이
  안 나온다. 그래도 C0에서 이항/과분산 검정으로 정식 기각을 남긴다.

## 4. 단계 설계

### C0 — 오프라인 포렌식 (라이브 자원 0, 먼저 끝낸다)

기존 산출물만 읽는다. 새 런 없음. 새 부하 없음.

1. **전 런 × 전 코호트 × 전 창**에 대해 커넥션별 위반율·`service_ms`
   분위수·send 지연을 뽑아 표로 만든다 (`pa_conn_edge.py` 확장).
   대상은 taskA 11런 + phase4 + demo 아카이브까지.
2. **열화 커넥션의 소스 포트**를 `envoy_access.log`에서 조인해 회수한다.
   포트값, `mod` 패턴, 배정 순서(= conn 인덱스)와의 상관을 본다.
   → H1의 1차 증거가 여기서 나올 수 있다. **비용 0이므로 반드시 먼저.**
3. 열화가 `conn` 인덱스(=생성기 goroutine 순서)와 상관되는지 본다.
   상관되면 생성기측(H4), 포트와만 상관되면 경로측(H1).
4. **시간 구조**: 열화 커넥션이 창 내내 나쁜지, 아니면 정체 구간이
   뭉쳐 있는지 초 단위로 그린다. 뭉쳐 있으면 "간헐 정체" 확정이고
   버스트 길이가 큐 깊이의 단서가 된다.
5. H5 정식 기각 (과분산 검정).

**게이트**: C0 결과로 H1~H4의 사전순위를 갱신한 뒤에만 C1로 간다.
포트 패턴이 명확히 나오면 C1을 통째로 건너뛸 수도 있다.

### C1 — 국소 재현 (짧은 런, 정책 무관)

복권을 **싸게, 반복적으로** 재현하는 최소 조건을 찾는다.

- 정책은 **고정 baseline 하나**(`bl_rr` 또는 `site_s2`)로 못 박는다.
  이 단계에서 SORTS 결정 로직은 변수에서 뺀다.
- 밴드만 걸고 60~90 s 짧은 런을 **n≥10** 돌려 열화 개수 분포를 얻는다.
  이게 이후 모든 감별의 **기준 분포**가 된다.
- 목표: "열화 개수 ~ 어떤 분포"를 정량화. 지금은 n=1 관측 몇 개뿐이다.

### C2 — 계층 절개 (감별 실험 본체)

C0/C1이 지목한 가설부터 §3의 감별을 실행한다. 한 번에 **한 계층만**
바꾼다. 각 조건 n≥5.

- qdisc 교체(H1) → UE 우회/host 주입(H2) → Envoy concurrency(H3) →
  커넥션×rps 재배분(H4).
- 매 조건마다 C1의 기준 분포와 비교한다.

### C3 — 판정 및 이관

- α/β 달성 시: 변경을 확정하고 **radio 축 핵심 비교를 재측정**한다.
  최소 T8/T9(radio) + T10/T11(edge) 재실행. 작업 A §3의 조건부 주장을
  무조건부로 승격할 수 있는지 판정.
- α/β 실패 시: **C-γ 프로토콜을 확정**하고(§5) 작업 A 보고서의 radio 축
  서술을 그 프로토콜 기준으로 다시 쓴다.
- 어느 쪽이든 ISSUES.md I-8을 **종결 또는 재정의**한다.

## 5. C-γ (측정 프로토콜) 후보 — 최소 산출물

기전을 못 밝혀도 이건 남겨야 한다.

1. **층화 추정량**: 커넥션을 정상/열화로 나눠 **조건부 효과**를 보고하고,
   열화 개수는 별도 확률변수로 취급한다. 작업 A §3이 이미 쓴 형태이므로
   정식화 + 임계값(현재 5 % 임의) 근거만 붙이면 된다.
2. **런내 페어링**: 같은 런 안에서 정책을 바꿔가며 arm을 비교한다
   (I-8은 런 사이에서만 문제가 된다 — §2.1). shadow/const-vs-both가
   이미 쓰는 방식이고, 이를 정책 비교로 확장할 수 있는지 검토.
   **이게 가능하면 사실상 문제가 해소된다 — 우선 검토할 것.**
   - ★**코호트 충돌 주의**: 두 정책을 동시에 돌리려면 코호트를 arm에
     배정해야 하는데, 그러면 **코호트가 곧 arm이 되어 코호트 비대칭
     실험(edge 축)과 충돌한다.** 따라서 (a) UE를 추가해 코호트 3개로
     늘리거나 (b) **시간 분할**(같은 런의 전반/후반)로 가야 한다.
     (b)는 열화 상태가 런 내에서 유지되는지에 의존한다.
   - **판정 (C0 완료)**: **(b) 성립.** 버킷 배정이 커넥션 수명 내내
     고정이라 열화 집합이 교란 창 전/후반 **완전히 동일**했다(세 런 모두,
     `TASKC_REPORT.md` §2.3). Phase 4의 "during 내 위반은 상시 상태"
     관측과도 일치한다. 남은 확인은 정책 전환 과도구간 배제 폭과
     순서 효과(순서 교차 반복으로 상쇄)뿐이다.
3. **반복 + 랜덤 순서**: 조건당 n≥5, 실행 순서 랜덤화, paired seed.
   드리프트와 추첨을 분리한다.
4. **커넥션 수 상향**: 16 → 32/64로 늘려 대수의 법칙으로 분산을 줄인다.
   단 총 rps를 유지해야 하고, 커넥션당 이용률이 바뀌면 H4가 개입하므로
   **C2의 H4 결과가 나온 뒤에** 판단한다.
