## §1. 목표와 산출 문장

**목표**: 무선 접속 상태(밴드)를 관측해 (코호트 × 클래스) 단위로 **허용 사이트
집합**을 제약함으로써, LB 가 보지 못하는 열화에서 SLO 위반을 줄인다.
SORTS 는 **LB 를 대체하지 않는다** — 집합만 좁히고 집합 안 선택은 Envoy
least-request 가 한다(`figures/ARCH_SPEC.md`).

**확정 산출 문장** (4단계 G2 확정):
> 최소 노출 요건은 **UE 그룹 단위 해상도**다(평균화 시 104배 악화).
> 갱신 주기는 서브초면 충분하나 **필요조건은 아니며**, 그 필요성은 밴드 변화
> 간격이 d\*=42.5 s 에 접근하는 환경에서 발생한다.

## §3. 관측과 결정

- 관측 2경로: **`rate`** ← `tc qdisc show dev ogstun`(설정값을 읽는다 — I-16),
  **`f_c`·응답 크기** ← front Envoy access log(윈도 `WINDOW_S` 2 s).
- 결정: `slack = SLO − GB − d_net − f_c − d_acc`, `d_acc = B×8/rate×1.10`.
  far-first 티어(`far_tier`)에서 slack>0 사이트를 허용 집합으로, 용량 초과
  사이트를 제거(`capacity_check`, HEADROOM 0.9), 전 집합 소진 시 손실 배분
  (`soft_assign`), 밴드별 유효 용량(`c_eff`) 적용.
- 제어 1경로: Envoy runtime key(`routing.<prefix>.<cluster>`), **변경 시에만** apply.
- **주기 T = 1 s 확정**(2단계). 근거는 "빨라서 좋아진 게 없다"가 아니라
  **주기를 40배 줄여도 잔여 위반이 116.7건으로 불변**이고 그중 97~99.5 %가
  `f_c` 비-fresh 구간에서 나온다는 것 — 병목이 주기가 아니라 관측 채널이다.
  유효 범위: 밴드 변화 간격 > d\* **42.5 s**(= 1.41 회/분 미만).

### §3-6. 용량 실측 (v4 §3-6 갱신)

- 등가 도착률 `eq = 1.000·search + 0.278·reserve + 0.178·recommend`
  (M0 에서 `eq = 0.47422 × 총 rps`). **측정 조성 볼록포 안에서만 유효.**
- `c_eq` = S1 279 / S2 515 / **S3 865(M0 조건부 — w 공유 불성립)**.
- **`C_eff(S1|밴드)` = 206.1(무제한) / 161.7(2300 k) / 105.4(1600 k) eq**
  — max-클래스 위반율 1 % 교차. **본 연구의 무릎 정의는 이것 하나로 통일**한다.
- 다른 무릎 수치와의 관계(정의 차이일 뿐, 실측 충돌 아님):
  search 단독 260(p95 예산 기준) = 225.6(1 % 기준) ↔ M0 혼합 206.1 —
  **기준 차 13 %, 조성 차 9 %**로 두 축이 각각 일정하다(STAGE5 G1 §1.2).
- `run_all.py:71` 의 `S1_KNEE_RPS = 400` 은 **보고 전용 상수**(판정 미사용).

## §4. 핵심 발견

### §4.1 예산 표 — 배정 이전에 무엇이 불가능한가 (v5 신설, 런 0)

`budget = SLO − GB − d_net − d_acc(class, band)` — **음수면 서버가 아무리
빨라도 SLO 를 못 맞춘다.** `analysis/stage6/budget_table.csv`, 그림 F2.

| 밴드 | search S1 / S2 / S3 | reserve S3 | recommend S3 |
|---|---|---|---|
| 무제한 | +38.0 / +25.0 / +15.0 | +5.0 | +5.0 |
| 4500 k | +29.3 / +16.3 / **+6.3** | +4.9 | +4.6 |
| 2300 k | +20.9 / +7.9 / **−2.1** | +4.9 | +4.2 |
| 1600 k | +13.4 / **+0.4** / **−9.6** | +4.8 | +3.9 |

**밴드는 클래스를 가려서 때린다** — 응답이 큰 search 만 무너지고
reserve·recommend 는 전 밴드에서 양수다. 실측 정합 두 건:
(1) 1600 k 에서 SORTS 의 search 가 S3 로 간 비율 **pre 41.5 % → both 0.0 %**
— 예산 −9.6 ms 칸을 **한 건도 쓰지 않는다**(F1 4단).
(2) 4500 k 는 S3 예산이 +6.3 이라 **정책 변별 자체가 없다**(야간 D2 0.06 %).
S2 @1600 k = **+0.4 ms** 는 양수지만 여유가 없어 순간 큐에 무너진다 —
L=1400 역전에서 S2_search 99.4 %가 그 결과다.

### §4.2 우위는 **두 축**에서 나온다 (v4 §4.2 확장)

v4 는 "우위는 무선이 아니라 용량 경계에서 나온다"였다. 부하 스윕 결과
**축이 둘**임이 드러났다.

1. **거리 × 밴드 축(층 1·2)** — 부하와 무관하게 저부하 전 구간에 존재.
   L=200(K비 0.42)에서도 `bl_lr` 대비 격차 **8.2 %p**. 기전은 용량이 아니라
   §4.1 의 구조적 예산 소진이다(S3_search 위반 100 %인데 `f_c` 3.8 ms).
2. **용량 경계 축(층 4·6)** — `bl_loc_pri` 대비. 격차가 **K비 1.49** 에서
   열려 K비 1.77(L=800)에서 최대.
3. **비교군에 따라 드러나는 축이 다르다**(lr → ①, loc_pri → ②). 논문 §6 에서
   비교군을 둘 다 둔 이유가 이것이다.
4. **수정 범위**: 야간 §4.2 의 "**radio 축 단독으로는 정책 변별 불가**"는
   *무선 축 스윕*의 판정으로 **그대로 유효**하다. 이번 확장은 *부하 축*이며
   두 축의 결론을 뭉뚱그리지 않는다.

### §4.3 경계의 위치와 유효 범위 (v5 신설)

> 격차는 무릎 아래에서 0 에 가깝고, 무릎의 **1.5~2 배** 구간에서 최대가 되며,
> 그 위에서 **부호가 반전된다.**

실측(L / K비(lr) / 격차): 200 / 0.42 / **+0.055** · 450 / 1.02 / +3.742 ·
800 / 1.77 / **+4.274** · 1400 / 2.33 / **−15.924 %p**.

> 우위의 유효 범위는 K비 약 2 까지다. 그 위에서는 SORTS 가 엣지를 보호하며
> 원거리로 밀어낸 부하가 원거리 사이트를 붕괴시켜 총 위반이 역전된다.

역전의 귀속(런 0 분해, STAGE5 §9): **(i) `C_eff` 테이블 비대칭 93 %** /
(ii) 진동은 (i)의 파생 / (iii) 총수요 초과는 격차 기여 0(양 정책 공통 하한
25.8 %p, `bl_lr` 은 하한 +5.1 %p 로 거의 최적).

### §6.3 산출 문장 (v4 문구 교체)

### §6.5 향후 과제 (v4 §11 대체)

1. **`C_eff(site × class × band)` 측정** — L=1400 역전 해소의 정공법.
   범위가 좁다: **예산 ≤ 0 칸은 런 없이 계산**되고(§4.1), 실측이 필요한 것은
   **유한 예산 칸 2개**(S2 search +0.4 ms, S3 recommend +3.9 ms)다.
   ⚠ 반사실 결과: **비례 축소 값으로 채우면 악화**한다(S3 몫 46 → 55 %).
   거리 보정 값에서만 S1 몫이 14.8 → 56.5 %로 뒤집힌다.
   ⚠ 채택하면 **결정 로직 수정 + 누적표 전체 재실행**이 따라온다.
2. **진동 완화(히스테리시스)** — 고부하에서 subset 전환이 800 의 24~31 →
   1400 에서 245~264 로 급증(I-9/I-13/I-17 계열의 고부하 발현). 완화는 이번
   범위 밖이었다.
3. **패킷 손실·재전송 축** — 현 무선 모형은 대역(rate) 단일 축이다. 손실/재전송이
   들어가면 `d_acc` 모형과 예산 표를 다시 세워야 한다.

  변한다"로 쓴다. 표준 준수 실험이 아니라 **노출 형태 모사**이며,

  **"지역 평균이라서"**다. §7 표에서 **granularity 열이 결정적이고 시간 척도
  열은 부차적**이다. 근거: 평균화 104배 vs 지연 2 s +0.09 %p.
- 채널 구분(2단계와 4단계의 외견상 모순 해소):
  > 관측 채널마다 신선도 요구가 다르다. 서버 지연 관측(`f_c`, `WINDOW_S`)은
  > 신선도가 지배하고, 무선 관측(`rate`)은 해상도가 지배한다.

## §9. 상시 규칙과 함정

### 규칙

1. **동결 6파일**(`sorts_ctl.py`·`obs.py`·`sorts.yaml.tmpl`·`run_all.py`·
   `gen_envoy_v10.py`·`envoy_keys.json`)은 명시적 해제 결정 없이 고치지 않는다.
   런 단위 가드가 md5 를 대조한다.
2. **사전 등록** 후 결과를 본다. 등록 전에 (a) 그 지표의 런 간 산포를 기존
   원자료로 확인하고, (b) **산식의 각 항이 같은 대상(정책·창·모집단)을 가리키는지**
   확인한다(`analysis/method_cases.md` B-4).
3. **계열 혼용 금지** — 같은 지표라도 계열이 다르면 값이 움직인다(`bl_lr`
   서버 축 0.075 ↔ 0.158 %). 섞으려면 브리지 런이 있어야 한다.
4. 판정은 **산출물 파일 기준**. 보고서의 수치는 대장에 등재된 것만.

## §10. 결정 사항 (확정 이력)

1. 무릎 정의 = `C_eff(S1|밴드)` 하나로 통일(STAGE5 G1).
2. HC 는 hc_off 로 통일하고 브리지 런으로 계열을 잇는다(STAGE5 G1 §1.2).
3. P-S5-4 는 **갈래 B**(무릎의 일정 배율 초과에서 격차가 열린다) 채택 —
   등록 산식이 두 정책을 교차 참조한 결함이었고, 결함이 만든 유리한 결론(A)을
   기각했다(STAGE5 G2 §2).
4. `C_eff(S2/S3)` 측정은 **하지 않는다** — 결정 로직 수정 + 헤드라인 재실행을
   요구하므로 논문 마무리 범위 밖. 향후 과제로 규격만 남긴다(§6.5).
5. 그림 주 그림은 총 부하 축, K비 축은 보조(정책별 K비가 달라 단일 정규화 불가).
