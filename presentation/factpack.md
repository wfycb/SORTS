### 2.5 컨트롤러 동작 요약

- **실행 위치**: `.43` (runtime_modify 가 `127.0.0.1:9901` 로컬 호출, ogstun 관측이 같은 호스트)
- **제어 주기** `T_ctrl` = **1 s**
- **관측** `get_access_state()`: `tc qdisc show dev ogstun` 의 netem `rate` 를 읽음.
  classid 상위비트로 코호트 구분(1:1xxx = c1, 1:2xxx = c2). 64개 leaf 의 최빈값 사용
  (apply 가 전체 재구축이라 도중 표본은 일부만 보일 수 있음)
- **결정식**:
  ```
  d_acc = 응답바이트 × 8 / rate × 1.10                       [ms]
  slack(site) = SLO − GB − d_net(site) − f_c(site,class) − d_acc
  선택 = S3 → S2 → S1 순서로 첫 slack > 0.  전부 음수면 S1 + EXPECTANT
  ```
- **적용**: 바뀐 유닛만 `POST /runtime_modify?routing.<코호트>_<클래스>.<클러스터>=…`
- **로깅** `decisions.csv`: ts, cohort, class, observed_rate_kbit, d_acc_ms,
  slack_s1/s2/s3, chosen_site, changed, apply_latency_ms, expectant

## 6. 한계와 다음 단계 (P5.3)

전체는 `limitations.md`. **영향 방향**을 명시했다.

| 한계 | 방향 |
| --- | --- |
| 관측 함수가 에뮬레이터 설정값을 읽음 (노이즈·보고 지연 없음) | **낙관** — 표 4 의 잔여 위반은 하한 |
| `f_c` 가 캐시 100% 적중 상태 (profile·rate 적중률 100.000%) | **낙관** — 절대값 인용 시 한정 필요 |
| 반복 n=1 | 중립 — d1 편차로 대리(CV 0.3~1.3%) |
| 서버 교란 대상 재선정 필요 | 중립 — `server_s1` 캘리브레이션 완료했으나 미사용 |
| 업스트림 DSB 버그 3종 유지 | 중립 — 세 사이트 동일 작용. 워크로드 서술 정정 필요 |
| `GB` 5 ms 근거 부재 | 중립 — slack 식의 상수 |
| UERANSIM 에 물리계층 없음 | 중립 — 외부 타당성 한계 |

**워크로드 서술 정정 (중요)**: "search 가 예약 가용성을 확인한다" / "예약이 쌓이면
search 가 느려진다"는 **쓸 수 없다**(업스트림 버그로 Mongo 폴백이 도달 불가 코드).
정확한 서술: *search 는 geo → rate → reservation → profile 의 4단 팬아웃을 만들며,
그중 reservation 단은 memcached 조회만 하고 영속 저장소에 접근하지 않는다.*
