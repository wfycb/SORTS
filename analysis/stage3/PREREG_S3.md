# STAGE3 사전 등록 (G1 회신 반영 확정판, 2026-08-12 — 본 배치 데이터 이전)

지시 §3.3 + G1 회신 §2.4·§3. 전부 본 배치 착수 전 등록.

## 1. 주 지표·판정 (지시 §3.1·§3.4)

- 총 부하 800 rps 고정. **교락 명시**: 코호트당 부하 400/200/133 rps 로
  변하므로 "코호트 수" 효과와 "코호트당 부하" 효과는 분리되지 않는다.
- 주 지표 = **비열화 코호트 위반율**(c2.. 전 코호트, during 창, 코호트 가중).
  열화 코호트(c1) 자신의 위반율은 **관측 항목 강등**(부하 변동 직접 노출).

## 2. P-S3-1 ~ P-S3-4

1. **P-S3-1**: c1 열화 시 비열화 코호트 위반율 < **0.05 %** (전 arm).
   2코호트 기존 실측 0.000 %. 실패 시 어느 arm·유닛이 새는지 특정 후
   정지·보고 (원인 추정으로 넘어가지 않음).
2. **P-S3-2**: 무교란(pre) 창 위반율 arm 간 최대차 ≤ **0.1 %p**.
3. **P-S3-3** (단위 승인분): stale 판정 단위는 **site×class** (전 코호트
   합산). 카운트 대상은 "**트래픽이 있는데** n_min 미달로 stale" 뿐 —
   트래픽-0 사이트의 prior 는 I-6 설계 거동이라 제외. 전 arm 에서 0 예측.
   발생 시 해당 arm 은 분리 실패가 아니라 **관측 조건 미달**로 분류.
4. **P-S3-4**: c1:search 플립 전환 횟수가 코호트 수에 따라 증가하지 않음
   + 비열화 코호트 유닛의 신규 플립 발생 여부 보고. 증가 시 I-17 입력.

## 3. P-S3-5 ~ P-S3-7 — 코호트 간 결합 경로 (G1 회신 §3, 주 질문 재정의)

관측 층(f_c 코호트 합산)이 **코호트 간 결합 경로**다: c1 이 열화로 S2 에
몰리면 f_c(S2) 가 오르고 그 값을 비열화 코호트도 함께 본다. 분리는 **정책
분리이지 물리 분리가 아니다.**

5. **P-S3-5 (결합 크기)**: c1 유입 목적지 사이트의 f_c(클래스별) 상승분
   Δf_c = during 창 obs p95 − pre 창 obs p95. arm 별 보고.
6. **P-S3-6 (잠식)**: 비열화 코호트 유닛의 slack 분포(중앙값·최소값)
   pre → during 변화. 최소값이 0 에 근접하는 유닛 명시.
7. **P-S3-7 (발현)**: 잠식이 실제 위반으로 넘어가는가 — P-S3-1 과 함께
   판정하되 **위반 0 이어도 잠식이 관측되면 보고** ("여유가 있어 안
   보였다" ≠ "결합이 없다").
8. **예측(등록)**: 결합은 존재하고, 크기는 코호트 수에 따라 커지지
   않는다(총 부하 고정 → 목적지 사이트 총량 동일). 발현은 비열화
   코호트의 잔여 여유에 달린다. 빗나가면 기전 특정 후 보고 — 정지 아님.

서술 방향(등록): 결함이 아니라 구조의 정직한 서술 — "코호트 분리는 배정
정책 수준에서 성립하며, 공유 자원(사이트 처리 용량)을 통한 간접 결합은
남는다. 그 크기와 발현 조건을 정량화했다."

## 4. 재현런 판정 대역 (해제 검증, G1 회신 §2.1)

2코호트 재현런 1회 (stage2 T=1 s config 동일): c1 search during 위반율 ∈
**0.708 ± 0.090 %** (= [0.618, 0.798]), 반응(발효 기준) ∈ **0.963 ±
0.016 s** (= [0.947, 0.979]) — ±1σ 밖이면 정지·보고. `read_rates` 동작
범위 확대(0x1000~0x6000)는 재현런(2코호트)과 6코호트 드라이런 양쪽에서
observed_rate 정상 관측으로 확인.

## 5. 앵커 (본 배치 게이트 — stage2 P-S2-0'' 승계)

## 6. 사후 확인 항목 (G1b 승인 회신 — pre 창 데이터로 판정, 본 배치 전 등록)

1. **커넥션 수 교락 (f_c S2/search 7.3→8.6 ms 단조 상승의 후보)**:
   manifest 구조상 **총 커넥션 = 16×n = 32/64/96 으로 arm 단조 증가**
   (코호트당 16 고정 — 포트-버킷 규약 유지 목적). 회신이 지목한 C_eff
   기전(커넥션 점유→동시성 잠식)과 같은 경로일 수 있다. G2 보고 요구:
   (a) arm별 총/코호트당 커넥션 명시, (b) pre 창 f_c(S2/search) arm별
   병렬 — c2<c4<c6 단조면 런간 변동 아님으로 판정하고 **"코호트 수" 효과와
   "커넥션 수" 효과의 교락**을 §3.1 교락 목록에 추가, P-S3-5 해석(baseline
   이 arm마다 다름)에 반영, (c) probe_buckets 통과 여부 arm별.
2. **비열화 코호트 밴드 확인**: 본 배치는 `radio(spec1=poor, spec2=none)`
   + 코호트 3+ 자동 "none" (run_all.radio 규약) — manifest 에 band_spec
   미지정이므로 **c2~cN 전부 무제한**. G2 보고에 manifest·마크 기준으로
   명시(좁은 밴드 혼입 시 P-S3-1/7 오염 — 드라이런의 혼합 밴드는 read_rates
   검증 전용이었음).
