### 1.2 교차 검증 — 정의 차이로 설명되는가

야간 원자료를 C_eff 와 **같은 산식**(1 % 로그-선형 보간)으로 재계산했다:

|---|---|---|---|
| 위반율 1 % 교차 | **225.6** rps = 225.6 eq | 206.1 eq (등록값) | **−8.6 %** |

| 기준 잔차(1 % vs p95) | −13.2 % | −13.1 % | — |

**두 기준에서 조성 잔차가 8.6 / 8.8 %로 같고, 두 조성에서 기준 잔차가
13.2 / 13.1 %로 같다.** 즉 eq 가중(1 / 0.278 / 0.178)이 조성 차이를 9 % 이내로

미발동.**

### 1.3 확정 제안 — 단일 정의 K

> **K ≡ C_eff(S1 | 밴드)** [eq], max-클래스 위반율 1 % 교차.
> 무제한 **206.1** / 2300 k 161.7 / **1600 k 105.4**.
> 수요도 같은 eq 단위로: `eq = 1.000·search + 0.278·reserve + 0.178·recommend`.

채택 이유: (a) 판정 지표(위반율)와 **같은 기준**이라 곡선과 무릎이 같은 축에
있다, (b) **밴드 조건별로 존재**해 `both` 창(1600 k)에 그대로 적용된다,
(c) 결정식이 실제로 참조하는 값(`c_eff_band` 테이블)이라 "정책이 무릎을
넘겼는가"가 정책 내부 기준과 일치한다, (d) 260 은 이 정의의 다른 기준·조성
표현으로 환산 가능(§1.2).

### 3.3 판정

1. **16 conn 은 L = 1400 에서 성립하지 않는다.** 밴드 창에서 달성 86.7 %,
   `corrected` p50 이 **3.5 초**로 폭주하는데 `service` p50 은 27.8 ms 로 멀쩡하다
   — 서버가 느린 게 아니라 **생성기 스레드가 스케줄을 못 따라간 것**이다
   (tb-load = 커넥션당 1 outstanding + 절대 스케줄 유지). 같은 부하에서 32 conn 은
   달성 100 %·밀림 0.3 ms·`service` p50 동일(27.8) — **생성기 구성 문제임이
   동일 부하 대조로 확정**된다.
2. **상단 점의 병목은 CPU 가 아니라 커넥션 동시성이다.** .12 CPU 최대 3.1 %
   (16 코어 i5-14400F) — 지시 §2.2.3 의 "생성 능력"은 CPU 여유가 아니라
   커넥션당 rps 상한(≈ 1/응답지연, 밴드 창에서 ≈ 33 rps/conn)으로 결정된다.
3. **L ≤ 800 은 16 conn 으로 성립**(밴드 both 창 달성 100.0 %, 밀림 0.2 ms) —
   앵커(taskB3 16 conn)와 같은 구성을 유지할 수 있다.
4. **S1 링크 100 Mb/s 포화 없음**: 프로브 전 구간 S1 NIC 최대 **9.9 Mb/s**
   (rx+tx, 516 표본) = 링크 **10 %**, S1 CPU 최대 19.2 %. 이는 `bl_rr` 기준
   (S1 몫 1/3)이므로 최악(`bl_loc_pri` 전량 × 1400)으로 외삽해도 ~30 Mb/s
   = 30 % — **링크는 스윕 상단에서도 제약이 아니다**. 원자료 `sample_s1.txt`.
5. **최고 부하 점에서 위반이 닫히는지**: 32 conn 1400 의 `bl_rr` both 위반은
   24.1 % 로 아직 100 % 가 아니다 — 즉 1400 은 "전 정책 붕괴로 격차가 닫히는"
   점일 수도, 아직 아닐 수도 있다. 이 확인 자체가 P-S5-1 의 오른팔 판정이다.
6. **부수 발견(P-S5-5 관련)**: `bl_loc_pri` 의 800 rps 붕괴(달성 74.8 %)를
   같은 방식으로 분해하면 `service` p50 36.1 ms / `corrected` p50 **65.1 초**
   — 밀림이 65 초까지 쌓인 **진짜 용량 초과**다. 1400@16conn 의 밀림(3.5 s,
   커넥션만 늘리면 사라짐)과 **기전이 다르다**. 이 대비가 §5.3 정정안의 판별식이다.

### 3.4 상단 점 커넥션 수 — 제안

### 5.3 P-S5-5 정정안 (프로브로 판별식 확보)

지시 원문("달성 rps 가 요청 대비 ±2 % 이내, 벗어난 점은 제외")을 그대로 적용하면
`bl_loc_pri` 의 800·1400 점, 즉 **P-S5-3 이 특정하려는 붕괴 점이 전부 제외**된다.
프로브가 두 미달의 기전을 갈랐으므로(§3.3-6) 다음으로 정정할 것을 제안한다:

> **P-S5-5′**: 달성 미달은 두 갈래로 분해해 판정한다.
> (a) **생성기 구성 부족 → 런 무효·재구성**: `service` 는 정상인데 밀림
> (`corrected − service`)이 누적하고, **같은 부하에서 커넥션을 늘리면 달성이
> 100 % 로 회복**되는 경우(실측: 1400@16conn 86.7 % → 32conn 100.0 %).
> (b) **시스템 용량 초과 → 결과로 채택**: 사이트 `f_c` 가 무릎을 넘고 `service`
> 자체가 상승하며 커넥션을 늘려도 해소되지 않는 경우(실측: loc_pri 800 —
> svc p50 36 ms, `f_c`(S1) search p95 132 ms, 밀림 65 s). 달성 rps 를 표에
> **병기**하되 결과로 남긴다.
> 전 런에서 요청/달성/밀림/오류코드/.12 CPU 를 보고한다. .12 CPU 는 보조 지표
> (프로브 최대 3.1 % — 이 테스트베드에서 생성 한계는 CPU 가 아니다).

### 5.4 실행 순서·등록
