## 6. P-S5-5 정정 제안 (G1 결정 요청)

등록 원문("전 런에서 달성 rps 가 요청 대비 ±2 % 이내, 벗어난 점은 결과에서
제외")을 그대로 쓰면 **P-S5-1/P-S5-3 이 겨냥하는 붕괴 점이 전부 제외된다.**
실측: `s1locpri_edge_1..3`(L = 800) 은 달성 **598.6/800 = 74.8 %** 인데, 이는
생성기 능력 부족이 아니라 **S1 포화로 응답이 늦어져 커넥션 스레드가 스케줄을
못 따라간 것**(tb-load = 커넥션당 1 outstanding, 절대 스케줄 유지)이다. 즉
미달 자체가 붕괴의 발현이다.

정정안 **P-S5-5′** — 미달을 두 기전으로 분해해 판정한다(판별식은 S5-0 프로브로
실측 확보):

1. **생성기 구성 부족 → 런 무효·재구성**: `service` 는 정상 수준인데 밀림
   (`corrected − service`)이 누적하고, **같은 부하에서 커넥션 수를 늘리면 달성이
   100 % 로 회복**되는 경우. 실측: L = 1400 @16 conn 달성 86.7 %·밀림 3.5 s
   → @32 conn 달성 100.0 %·밀림 0.3 ms(`service` p50 은 27.8 ms 로 동일).
2. **시스템 용량 초과 → 결과로 채택**: 사이트 `f_c` 가 무릎을 넘고 `service`
   자체가 상승하며 커넥션을 늘려도 해소되지 않는 경우. 실측: `bl_loc_pri`
   L = 800 달성 74.8 %, `service` p50 36.1 ms, `f_c`(S1) search p95 132 ms,
   밀림 **65 s**. 달성 rps 를 표에 **병기**하되 결과로 남긴다 — 위반율은
   완료 요청 모집단 기준이므로 지표 정의는 불변이다.
3. 전 런에서 요청/달성/밀림/오류코드/.12 CPU 를 보고하고, **판별을 적용한
   런은 어느 갈래((a)/(b))로 분류했는지 런별로 명시**한다(G1 회신 §1.4).
   **.12 CPU 는 보조 지표**다 — 프로브 최대 3.1 %(16 코어)로, 이 테스트베드의
   생성 한계는 CPU 가 아니라 커넥션 동시성(밴드 창 ≈ 33 rps/conn, I-19)이다.

  `bl_loc_pri`(`s1locpri_edge_1`)는 post 120 s **전 구간 위반 100 %** 이고
  밀림이 73.6 → 99.3 s 로 **계속 증가**한다 — 120 s 로도 복구가 관측되지
  않으므로 축소가 자르는 지표가 없고, 관측 대상인 **밀림 증가 기울기**
  (0.234 s/s)는 60 s 창에서도 동일하게 추정된다. **판정: 영향 없음.**
- **1400 점 해석 규칙**: 이 점만 conn 이 다르므로, `800×32 conn` 대조와
  `800×16 conn` 본런의 차이(Δ_conn)를 반드시 병기하고, 1400 격차를
  Δ_conn 과 함께 해석한다(단독 수치로 결론 내지 않는다).
- **실행 순서**: 라운드 1 = 부하 오름차순 × 정책 SORTS→lr→loc_pri 각 1런,
  라운드 2 = 같은 순회를 **정책 역순**으로, 대조 2런은 마지막. 드리프트가
  두 반복에 같은 방향으로 실리지 않게 한다.
