# Phase 4 server 축 밴드 선정 — 6,000 kbit (c1만, c2 무제한)

2026-08-07. Phase 4 지시 §2(수정 1) 이행 기록. 계산 도구:
`obs_band_margin.py --stressed-fc-lo ... --obs-fc-normal-hi ... --band 6000`
(이번에 추가한 모드), 입력 분포는 `scratchpad/fc_windowed.py` (s6 재집계).

## 입력 — 캘리브레이션 실측 (지시서의 2.50×/f_c~10 가정 정정)

s6 런 `S3_cpu2_load80_rps800_site_s3` 의 envoy.log.gz 를 클래스별로 재집계.
슬라이스 검증: 전 클래스 합산 p95 4.059/10.112 ≈ result.json 4.059/10.138.

| 클래스 | 무교란 f_c p95 (48s) | 스트레스 f_c p95 (48s) | 상승 | 2s 윈도 p95 범위(스트레스) |
|---|---|---|---|---|

| reserve | 1.123 | **5.285** | 4.71× | 3.542 ~ 7.491 |

지시서의 2.50×는 전 클래스 합산 값이다. search 단독으로는 2.94×
(4.53→13.29)라 지시서 산술(임계 ~7,874)보다 대비 구간 상한이 크다.

## 대비 구간 (search, S3 스트레스, S3→S2 플립)

유지 임계 t_keep: 관측판 무교란 윈도 p95 최대 4.875 + 바이트 큰 상태
4632 기준 → **4,026 kbit**. (상수판 prior 4.019 기준 3,585, 바이트 갈림존
상한 3,712 — 전부 이 아래.)
기각 임계 t_rej: 스트레스 최약 윈도 10.904 + 바이트 4474 기준 → **9,612 kbit**.

**대비 구간 = (4,026, 9,612) kbit. 선택 = 6,000 kbit** (기하 중앙 부근).
- 유지 여유 +49%: 무교란 구간에서 관측 노이즈로 S3 를 버리려면 f_c 관측이
  8.21 ms 를 넘어야 한다 (실측 무교란 최대 4.88 — 3.3 ms 헤드룸).
- 기각 여유 +38%: 스트레스 최약 윈도(10.904)에서도 S3 기각이 성립.
- 갈림존 3개(3585-3712 / 1901-1968 / 1266-1311) 전부 밖 (기존 검사 통과).
- 커넥션 단위 셰이핑(radio v2)이라 포화 없음: 커넥션당 유입 ~0.35 Mbit/s,
  이용률 6%.

## 클래스별 대비 성립 여부 (search 우선 방침)

- **search: 성립** — 이 축의 주 지표.
- **reserve: 밴드로 제어 불가** — 스트레스 f_c p95(5.29)가 SLO 여유
  (35−5−25=5 ms)를 넘어 **어떤 밴드에서도** 관측판이 S3 를 버린다. 단
  최약 윈도(3.54)는 5 미만이라 스트레스 중 S3↔S2 **진동이 예상**된다.
- **recommend: 밴드로 제어 불가** — 스트레스 윈도(3.7~5.6)가 플립 임계
  (c1@6000: 4.71, c2: 5.0)에 걸쳐 있어 마찬가지로 **진동 예상**.

이 진동은 반응형 제어가 임계 근방 관측 노이즈에 노출되는 구조적 현상으로
**사전 예측**해 둔다 (I-6 스테일 낙관 점프와는 발생 기전이 다름 —
`f_c_src` 전환 시계열로 구별해 계측). 관측되면 §5/정지 7에 따라 완화책
투입 전에 정지·보고한다. 예상 밖인 것은 search 유닛의 진동이다 (여유
+38%/+49%라 나오면 안 된다).

## 상수판 예상 신호 크기 (참고)

≈ 윈도 p95 중앙값 — during 위반율 ~5% 수준 예상 (전런 환산 ~1.7%).
