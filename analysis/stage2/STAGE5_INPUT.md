# 5단계로 넘기는 입력 — 관측 채널의 성격 (§6.3 "Ideal" 행 재정의)

2026-08-11, STAGE2 §4 회신 §6-3 지시. **이번 범위에서 실행하지 않는다**
(기록·이관 전용). 근거는 `INJECT_PROBE_RESULT.md`, `V3_PRIMITIVE_REPORT.md`,
ISSUES **I-16**.

## 1. 실측 사실

- `rate_kbit` 는 **`tc qdisc show dev ogstun` 의 netem `rate` 속성**을 파싱한
  값이다 — 커널에 설정된 셰이핑 **지시값**이며 처리량·RTT·바이트 카운터 같은
  트래픽 **측정이 아니다**(`sorts_ctl.read_rates`, factpack §2.5).
- 따라서 이 채널은 **보고 지연 0, 관측 오차 0** 이다. 값이 이산적으로
  정확하고, 스테일 개념도 없다(매 tick 직접 읽음).
- 구 primitive(v2)에서는 한 발 더 나아가 **물리적 발효보다 0.34 s 먼저**
  보였다(가시화 +0.26 s vs 발효 +0.60 s). v3 교체로 그 시간 간극은 제거했지만
  (가시화 ≡ 발효), **"지시값을 읽는다"는 성격 자체는 그대로다.**

## 2. 함의 — §6.3 표의 행 이름을 바꿔야 한다

현재 SORTS 의 무선 관측은 "이상적(Ideal) 관측"이 아니라 **상한(oracle)** 이다.
실제 배치에서 이만큼 정확·즉시인 채널은 존재하지 않는다. 따라서:

| 행 | 현재 표기 | 바뀌어야 할 표기 | 성격 |
|---|---|---|---|
| SORTS 무선 관측 | Ideal | **Oracle (상한)** | 지시값 직독 — 지연 0·오차 0. 달성 불가 상한 |
| RNIS-like | — | 그 아래 | RAN 이 주기 보고 (보고 주기·양자화·지연 존재) |
| NWDAF-like | — | 그 아래 | 코어 분석 기능 경유 (집계 지연 더 큼) |
| 측정 기반 | — | 최하 | 트래픽에서 역추정 (샘플 필요·열화 후에만 관측) |

즉 논문의 무선 축 결과는 **"이 정보가 있다면 얻는 상한"** 으로 읽어야 하고,
RNIS/NWDAF 열화 모형(보고 주기 Δ, 양자화 q, 지연 d)을 얹은 감쇠 곡선이
현실 구간을 채운다. 5단계에서 이 감쇠를 실험 축으로 세우면 "상한 → 현실"의
연속체가 만들어진다.

## 3. 5단계 설계 제안 (미실행)

1. **관측 열화 주입**: `read_rates()` 를 건드리지 말고, 컨트롤러 입력단에
   래퍼를 두어 (a) 보고 주기 Δ ∈ {0.1, 0.5, 1, 2 s}, (b) 양자화 q(밴드
   계단), (c) 지연 d 를 적용한 값을 쓰게 한다. 코드 변경은 래퍼 1개로
   국한되고 결정 로직은 불변이므로 동결 정책과 충돌하지 않는다.
2. **측정 기반 대조군**: 트래픽에서 하향 처리량을 추정하는 관측기(예:
   응답 바이트/전송 시간)로 같은 결정을 돌려 "측정으로도 되는가"를 본다 —
   이것이 진짜 배치 가능성 논거다.
3. **판정 축**: 주기 ablation(2단계)이 이미 "T 단축의 이득이 작다"를 보이면,
   5단계의 관심은 **T 가 아니라 Δ·q·d** 로 옮겨간다. 두 결과를 묶으면
   "제어 주기보다 관측 채널의 품질이 지배한다"는 서사가 성립한다(가설 —
   실측 전).
