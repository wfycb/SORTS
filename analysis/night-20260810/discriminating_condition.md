## 핵심 판정

**1. radio 축 단독으로는 정책 변별이 불가능하다 — 확정.**
부하가 S1 search 무릎(과제1 실측 260rps) 아래면 극단 밴드(1600k)로도 안 갈린다:
총부하 500(유입 166rps)→Δ0.16, 600(200rps)→Δ0.13, **800(266rps)→Δ24.0**.
변별 경계가 무릎과 정확히 일치(총부하 ~780 = 260×3). 완화 밴드(4500k)는
부하 800에서 위반 자체가 없다(D2, 0.06%). **변별 조건 = 극단 밴드 × 무릎 초과
부하의 곱**이고, 이는 과제 2가 쓴 조건 그 자체다(양 코호트 극단 창이 유일한
검증된 radio-변별 창으로 유지).

**2. D1(4500k×1400)의 Δ5.9%p 는 radio 가 아니라 부하 축의 것이다.**
pre 창(밴드 없음, 1400rps): far_tier **0.2%** vs strict_far **68.9~71.5%**.

strict 실패의 기전 (사후 검증 완료, 08:05):
- **pre 창에서 이미 진동**: strict 인데 pre site_share = S2 41.7%/S3 58.3%,
  decisions.csv 유닛당 S2 630틱/S3 651틱 왕복. 부하 1400 만으로 —
  S3 관측 f_c p95 27.3ms > S3 search 예산 10.98ms → 기각 → S2 이동 →
  S2 는 자기 무릎(혼합 SLO 1000, t1c 실측) 초과라 **진짜 과부하**(service
  p95 search 115.6ms) → 기각 → S3 복귀. I-9 되먹임 진동의 무교란·고부하 발현.
- **S3 물리 용량 탓이 아니다**: 같은 밤 t1c 실측 — site_s3 고정 직접 부하
  1400~1600rps 에서 위반 0.1~1.0%, f_c p95 5.8~14.3ms. S3 는 1400 을 받을 수
  있다. strict 가 못 쓰는 이유는 관측 f_c(27ms)가 예산(10.98)을 넘기 때문
  — d_net 25ms 가 SLO 예산을 다 먹는 사이트에 전량을 실으려는 정책 의미론과
  보수적 예산의 상호작용이다.
- **커넥션 HOL 도 중첩**: pre 의 corrected p95 213~239ms vs service p95
  48~116ms — 위반의 상당분은 커넥션 대기(생성기 모형 성질). 서버 과부하
  (S2 체류 구간)와 HOL 이 함께 만든 69%다.
- far_tier 는 700/700 분산으로 두 사이트 모두 무릎 아래 → 안정 0.2%.
- 밴드(4500k)는 far_tier 를 0.3→36%(during)로 올리는 부차 압력.

→ 이 조건은 "무선 교란 변별"이 아니라 **용량 초과 부하에서 티어 분산의
원리적 우위 + strict 류 단일 사이트 정책의 진동 취약성**을 보여준다.
작업 B 의 서버/부하 축 근거로 D1 pre 창(Δ~70%p, 무교란)이 가장 강력하지만
n=1 + 진동·HOL 혼합 기전이므로 승격 아님 — 반복과 기전 분해(HOL 몫 분리)가
필요하다.

**3. D4(2300k×1400): 양쪽 100% 포화 — 퇴화 조건.**
해석 단계의 "far_tier 가 S2 를 과적재해 역전" 예측은 판정 불가(둘 다 전멸).
post 창 위반 69~91%는 backlog 배수 오염 — 이 조건은 생성기 복구 한계도 넘는다.
