## 무릎 판정 (사전 등록 정의, 최종)

- **search 단독**: 2배 규칙(기저 6.72×2=13.4) → **240 rps**.
  SLO 예산 규칙(f_c p95 > 38ms) → **260 rps** (240=25.0 < 38 < 260=49.1).
  260→280 사이에서 25→118ms 로 폭주 — 무릎이 매우 날카롭다. C1 실측(266rps
  svc p95 92ms)이 260(51.4)과 280(120.0) 사이에 정확히 들어온다.
- **혼합**: 2배 규칙 → 150 (기저 4.05가 낮아 조기 발화; 150~300 이 8.2~9.8로
  평평한 것을 보면 기저 노이즈 — 판정 부적합으로 기각하고 SLO 규칙 채택).
  SLO 예산 규칙 → **500 rps** (400=14.0 < 38 < 500=43.9), 600 은 전면 붕괴.
- reserve/recommend: 혼합 600에서만 SLO 예산(28ms) 초과 — S1 제약은 전
  구간에서 **search 가 먼저** 깨진다.
- ★**혼합-단독 상호작용**: 혼합 500 의 search 는 167rps 인데 f_c p95 43.9 —
  단독 160rps(8.6)의 5배다. reserve/recommend 333rps(소형 요청)가 search 를
  잠식한다. **클래스별 용량은 조성(mix) 의존적** — 작업 B 의 용량 모형은
  "search 단독 등가 rps" 같은 가중 합으로 취급해야지, 클래스별 독립 한계로
  두면 틀린다. (등가 계수 추정: 혼합 500 ≈ 단독 255~260 상당 → r/r 1rps ≈
  search 0.27rps 상당. 추측 수준, 2점 보간이므로 참고만.)

## "혼합 400은 분모가 될 수 없다"의 수치화

- 혼합 400 rps 중 search는 133 rps(f_c p95 14.0) — 같은 S1이 search 단독으론
  240에서 이미 25.0ms. **클래스 구성이 다르면 같은 '총 rps'가 전혀 다른 부하다.**
  클래스 선택적 라우팅의 분모는 클래스별 용량이어야 하고, S1의 유효 제약은
  search ~240 rps(2배 무릎)/~250-270(SLO 추정)이다.
- C1의 "S1 한계 ~200rps 가정"은 무부하 무선 기준으론 보수적(실측 SLO 무릎
  260)이지만, **극단 밴드(1600kbit) 하에서는 거의 정확**했다: 밴드 코호트의
  corrected ≈ f_c + d_acc(≈26.6) + d_net(2) ≤ SLO 45 를 만족하려면 f_c p95
  ≤ 16.4ms → 단독 곡선 보간으로 **~210-220rps**. 용량 한계는 무선 상태와
  결합해 있다(SLO 예산을 d_acc 가 잠식하므로).
